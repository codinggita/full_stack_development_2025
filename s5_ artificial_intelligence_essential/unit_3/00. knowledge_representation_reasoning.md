# Knowledge Representation & Reasoning

## 1. Knowledge Representation — The Big Picture

### 1.1 What is "Knowledge Representation"?

#### Simple Meaning

**Knowledge Representation** is a **field of AI** which is the **process of translating human language** (which is complex, messy, made of facts and rules) **into proper mathematical logic**, so that it can be used to do the **reasoning part** and take the **final decision** to acquire/generate/get the final result.

**In the simplest words:** Humans don't naturally speak in strict, unambiguous logic — we speak in loose, "messy" sentences full of implied meaning. But a machine (an AI system) can only compute over **precise mathematical structures**. Knowledge Representation is the **translation layer** that sits between the two — it converts a human's fuzzy statement into something a machine can logically manipulate, check, and reason over.

#### Everyday Analogy

Think of a **tool like ChatGPT**. A human interacts with it using ordinary **human language** — full sentences, questions, implied context. But under the hood, the AI can't "just understand" a sentence the way a human intuitively does — the sentence first needs to be broken down into **facts, rules, and structured logic** before any reasoning or decision-making can happen on top of it.

```
KNOWLEDGE REPRESENTATION — THE TRANSLATION PIPELINE

   HUMANS                                    AI TOOL (e.g. ChatGPT)
   ──────                                    ──────────────────────
   "human language"        ──interact──►        "binary language"
   (fact, actual work,                                 │
    messy statement)                                   ▼
                                              ┌────────────────────┐
                                              │ KNOWLEDGE          │
                                              │ REPRESENTATION     │──► translates messy human
                                              │ (this field of AI) │     statement into proper
                                              └─────────┬──────────┘     MATHEMATICAL LOGIC
                                                        ▼
                                              ┌─────────────────────┐
                                              │     REASONING       │──► uses that logic to
                                              │   (using the logic) │    take a final decision
                                              └─────────┬───────────┘
                                                        ▼
                                             acquire / generate / get
                                                   FINAL RESULT
```

***

### 1.2 The 5 Stages of Knowledge Representation

| Stage | Name | What It Covers |
| :-- | :-- | :-- |
| **(i)** | **Representation** (Mathematical / Semantic Logic) | Splits further into two types — **Propositional Logic** and **Predicate Logic** (see Section 1.3 below) |
| **(ii)** | **Rule** | If–then style conditions that connect facts together |
| **(iii)** | **Frame** | **Structured & object-oriented** representation of knowledge |
| **(iv)** | **Semantic Net** | A **graph-based** representation (nodes + relations). Example: **Google Maps** — places as nodes, routes/relations as edges |
| **(v)** | **Script** | A representation of a stereotyped sequence of events (a pre-written "scenario" structure) |

```
STAGES OF KNOWLEDGE REPRESENTATION

  (i) Representation ──┬──► Propositional Logic
     (Mathematical/    └──► Predicate Logic
      Semantic Logic)

  (ii) Rule

  (iii) Frame ────────► Structured & Object-Oriented

  (iv) Semantic Net ───► Graph (nodes + edges)   e.g. Google Maps

  (v) Script
```

This document focuses on the **first stage — Propositional Logic** — in full depth.

## 2. Propositional Logic

### 2.1 What is "Propositional Logic"?

#### Simple Meaning

**Propositional Logic** is built from two core ideas:

1. **Proposition** → a **"Descriptive Statement."**
2. **Logic** → a **mathematical relation / logical implication.**

Put together, Propositional Logic is the branch of Knowledge Representation that deals with **statements (in human language, semantically)** that are **either True or False** — never both, never neither — and the **mathematical rules** used to connect and manipulate them.

```
PROPOSITIONAL LOGIC — CORE IDEA

           PROPOSITION                        LOGIC
      ("Descriptive Statement")      (Mathematical relation /
                                        logical implication)
                │                              │
                └──────────────┬───────────────┘
                                ▼
                     "human language statement"
                          (semantic)
                                │
                        ┌───────┴────────┐
                        ▼                ▼
                     TRUE              FALSE
                (must be exactly ONE of these — never both)
```

#### Everyday Analogy

Think of a **light switch** — it's either ON or OFF, there's no in-between, no ambiguity. A **proposition** works the same way: it's a statement that is definitely **True** or definitely **False**, with nothing fuzzy about it. *"Today rain will come"* is a proposition — it will turn out to be either true or false, but it's never a matter of opinion or degree.

***

### 2.2 Types of Statements in Propositional Logic

Every statement in Propositional Logic falls into one of **two categories**:

| Type | Meaning | Example |
| :-- | :-- | :-- |
| **Atomic** | A statement which **cannot be divided further** into smaller sub-statements | *"Today rain will come"* → represented as **P** |
| **Complex / Compound** | A statement which **can be divided** into smaller sub-part statements, connected together by a **rule/condition** | *"If rain will come then stop the sprinkler"* → made of two atomic parts joined by a rule (**If → then**) |

```
STATEMENT TYPES

              STATEMENT (Semantic, True/False)
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
       ATOMIC                    COMPLEX / COMPOUND
  (cannot be divided          (CAN be divided into smaller
   further)                    sub-statements, joined by a
                                rule/condition)
          │                           │
   "Today rain will come"    "If rain will come then
           P                  stop the sprinkler"
                                 (P)  (rule)   (Q)
```

***

### 2.3 The 5 Logical Connectives (Building Complex/Compound Statements)

Complex/compound semantic statements are built by joining atomic statements (`P`, `q`, `r`, ...) using these **5 connectives** — every connective translates a human-language word into a piece of **mathematical logic**:

| # | Connective | Symbol | Operator Name | Human-Language Word |
| :-- | :-- | :-- | :-- | :-- |
| (i) | **Negation** | `¬` (or `~`) | **not** operator | "not" |
| (ii) | **Conjunction** | `∧` | **and** operator | "and" |
| (iii) | **Disjunction** | `∨` | **or** operator | "or" |
| (iv) | **Implication** | `→` | — | "If ... then ..." |
| (v) | **Bi-directional (Biconditional)** | `↔` | — | "if and only if" |

```
STATEMENT  ──►  MATHEMATICAL LOGIC   (via these 5 connectives)

    ¬ (Negation)        →   NOT
    ∧ (Conjunction)     →   AND
    ∨ (Disjunction)     →   OR
    → (Implication)     →   IF ... THEN
    ↔ (Bi-directional)  →   IF AND ONLY IF
```

***

### 2.4 Worked Translation Examples (Human Language → Mathematical Logic)

#### Example 1 — Disjunction + Negation

> **"You can access the campus internet if you are a CSE student or not a fresher one."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `P` | You can access the campus internet |
| `q` | You are a CSE student |
| `r` | A fresher one |
| `¬r` | Not a fresher one |

**Rule/Condition:** "if ... or ..." → Implication + Disjunction

**Translated Mathematical Logic:**
```
P → (q ∨ ¬r)
```

***

#### Example 2 — Conjunction + Implication

> **"If the Security Sensor detects motion and System is armed, then the alarm will sound."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `P` | The Security Sensor detects motion |
| `q` | System is armed |
| `r` | The alarm will sound |

**Rule/Condition:** "If ... and ... then ..." → Conjunction + Implication

**Translated Mathematical Logic:**
```
(P ∧ q) → r
```

This is a classic **Compound/Complex Semantic** statement — two atomic facts joined with `∧`, and the whole thing feeding into an implication.

***

#### Example 3 — Disjunction + Biconditional

> **"You will pass the final exam if and only if you attend all the lectures or submit the extra credit project."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `P` | You will pass the final exam |
| `q` | You attend all the lectures |
| `r` | Submit the extra credit project |

**Rule/Condition:** "... if and only if ... or ..." → Biconditional + Disjunction

**Translated Mathematical Logic:**
```
P ↔ (q ∨ r)
```

***

### 2.5 Truth Tables

#### 2.5.1 Why We Need Them

Once a human statement is translated into logic (like `P → (q ∨ ¬r)`), a **Truth Table** is used to check the statement's truth value across **every possible combination** of True/False for its variables.

#### 2.5.2 Sizing a Truth Table

| Rule | Formula | Meaning |
| :-- | :-- | :-- |
| **Minimum number of columns** | `= total number of variables` | For `P → (q ∨ ¬r)` → 3 variables → **minimum 3 columns** (plus extra helper columns for intermediate steps) |
| **Exact number of rows** | `= 2^(number of variables)` | 3 variables → **2³ = 8 rows** (every possible T/F combination must be listed) |

```
"total no. of variables" = 3   (P, q, r)

        min. no. of columns = 3
        exact no. of rows   = 2^3 = 8
```

#### 2.5.3 Full Worked Truth Table for `P → (q ∨ ¬r)`

| P | q | r | ¬r | q ∨ ¬r | P → (q ∨ ¬r) |
| :-: | :-: | :-: | :-: | :-: | :-: |
| T | T | T | F | T | **T** |
| T | T | F | T | T | **T** |
| T | F | T | F | F | **F** |
| F | T | T | F | T | **T** |
| F | F | T | F | F | **T** |
| T | F | F | T | T | **T** |
| F | T | F | T | T | **T** |
| F | F | F | T | T | **T** |

All **8 rows** (2³ combinations) are covered — the statement is **False in only one case**: when `P=T, q=F, r=T` (you're not a CSE student, you are a fresher, yet you claim internet access — logically inconsistent).

***

### 2.6 Truth Rules for Each Connective

#### (i) Negation (`¬`) — "not" operator

| Input | Output |
| :-: | :-: |
| T | **F** |
| F | **T** |

Simply **flips** the truth value.

#### (ii) Conjunction (`∧`) — "and" operator

> **True only when BOTH sides are True.**

| P | q | P ∧ q |
| :-: | :-: | :-: |
| T | T | **T** |
| T | F | F |
| F | T | F |
| F | F | F |

#### (iii) Disjunction (`∨`) — "or" operator

> **True if EITHER side is True** (or both).

| P | q | P ∨ q |
| :-: | :-: | :-: |
| T | T | **T** |
| T | F | **T** |
| F | T | **T** |
| F | F | F |

#### (iv) Implication (`→`) — "If ... then ..."

> **False ONLY when the "if" part is True but the "then" part is False.** In every other case, it's True (even when the "if" part is False — a False premise makes the implication vacuously True).

| Case | Result |
| :-- | :-: |
| `T → T` | **T** |
| `F → T` | **T** |
| `F → F` | **T** |
| `T → F` | **F** (the ONLY false case) |

#### (v) Bi-directional / Biconditional (`↔`) — "if and only if"

> **True only when BOTH sides MATCH** (both True, or both False).

| Case | Result |
| :-- | :-: |
| `T ↔ T` | **T** |
| `F ↔ F` | **T** |
| `T ↔ F` | F |
| `F ↔ T` | F |

```
BI-DIRECTIONAL SUMMARY
   T ↔ T  ⎫
           ⎬ → T   (matching values → True)
   F ↔ F  ⎭
```

## 3. Summary Table — All 5 Connectives at a Glance

| Connective | Symbol | Word | True When... |
| :-- | :-: | :-- | :-- |
| **Negation** | `¬` | not | Input is False (flips the value) |
| **Conjunction** | `∧` | and | **Both** sides are True |
| **Disjunction** | `∨` | or | **At least one** side is True |
| **Implication** | `→` | If...then | Anything **except** `True → False` |
| **Biconditional** | `↔` | if and only if | **Both sides match** (T↔T or F↔F) |

***

## 4. Why This Matters (Recap)

Propositional Logic is the **first and most foundational stage** of Knowledge Representation. It gives AI systems a precise, mathematical way to:
1. **Translate** messy human statements into unambiguous logic (`P`, `q`, `r`, and connectives).
2. **Verify** every possible truth combination via a **Truth Table**.
3. Feed that verified logic into the **Reasoning** stage, so the system can take a **final decision** and produce a result.
