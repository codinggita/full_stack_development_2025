# Predicate Logic

## 1. Recap — Where Predicate Logic Fits

```
KNOWLEDGE REPRESENTATION — FLOW CHART

  Representation ──┬──► Propositional Logic  (True/False)
                   └──► Predicate Logic  (First Order Logic)

  Rules        (If → then)
  Frame        (Structured & Object Oriented)
  Semantic Net (Statement/Object representation in a graph format with relation)
  Script       (How it will work along with certain/specific terms & conditions)
```

Propositional Logic (covered in `00. knowledge_representation_reasoning.md`) handles simple **True/False statements** — `P`, `q`, `r` — joined by connectives (`¬, ∧, ∨, →, ↔`). But it has a limitation: it can't express statements about **groups, categories, or "how many"** of something something is true for. That's exactly the gap **Predicate Logic** fills.

***

## 2. What is "Predicate Logic"?

### 2.1 Simple Meaning

**Predicate Logic** is a **method/process** which falls under (belongs to) the **Knowledge Representation** field, used to **translate a semantic statement into 100% mathematical logic**, on which we can do the **reasoning** and get the **result / take an appropriate decision.**

It is an **extension / optimized version** of Propositional Logic — it covers the **remaining stuff/field/area/parameter that was NOT covered** by the earlier method (Propositional Logic).

**Example:** *"All apples belong to the fruit category."*

Notice this statement talks about **a whole category ("all apples")** — Propositional Logic has no built-in way to express "all" or "some" of a group; it can only assign one True/False value to one fixed statement. Predicate Logic introduces **variables, predicates, and quantifiers** specifically to handle this.

### 2.2 Everyday Analogy

Propositional Logic is like a **light switch** — one fixed statement, one fixed True/False answer. Predicate Logic is like a **spreadsheet filter** — instead of asking "is *this one* apple a fruit?", you can ask "is it true for **every** apple?" or "is it true for **at least one** student?" It lets you reason about **entire categories/domains** of objects at once, not just single isolated facts.

```
PROPOSITIONAL LOGIC                    PREDICATE LOGIC (extension)
────────────────────                   ────────────────────────────
One fixed statement                    Statements about VARIABLES
   P = "Today rain will come"          ranging over a DOMAIN/CATEGORY
   → True or False. Done.                 Apple(x) = "x is an apple"
                                          Fruit(x) = "x belongs to fruit category"
                                        → Can express: "ALL apples are fruit"
                                          or "SOME students are good at cricket"
```

## 3. Building Blocks of Predicate Logic

| Term | Meaning | Example |
| :-- | :-- | :-- |
| **Predicate** | A property or relation that becomes True/False once you plug in a specific object | `Apple(x)` = "x is an apple", `Fruit(x)` = "x belongs to the fruit category" |
| **Variable** | A placeholder (commonly `x`) standing in for "some object" from a domain | `x` in `Apple(x)` |
| **Domain** | The set of all possible objects the variable `x` can be replaced with | e.g. the set of all students, or the set of numbers `{0,2,4,6,8}` |
| **Quantifier** | A symbol that says **how many** objects in the domain the statement applies to | `∀` (Universal) or `∃` (Existential) — see Section 4 |

***

## 4. The Two Quantifiers

### 4.1 Universal Quantifier (`∀`)

- **Symbol:** `∀x` — read as *"For all x"*
- **Represents:** the **"All / Each"** category — the statement must hold for **every single object** in the domain.
- **Connecting rule:** when writing a universal statement joining two predicates, use **implication `→`**.

### 4.2 Existential Quantifier (`∃`)

- **Symbol:** `∃x` — read as *"There exists an x"*
- **Represents:** the **"Some / Partial"** category — the statement only needs to hold for **at least one** object in the domain.
- **Connecting rule:** when writing an existential statement joining two predicates, use **conjunction `∧`**.

### 4.3 Points to Remember (Key Rule)

| Quantifier | Symbol | Category | Connective Used Between Predicates |
| :-- | :-: | :-- | :-: |
| **Universal Quantifier** | `∀x` | All / Each | **`→`** (implication) |
| **Existential Quantifier** | `∃x` | Some / Partial | **`∧`** (conjunction) |

```
WHY THIS RULE MAKES SENSE

  ∀x  P(x) → Q(x)
      "For EVERY x, IF x has property P THEN x also has property Q"
       — using → naturally captures "whenever P is true, Q must follow,
          for all x" — exactly what "ALL" needs.

  ∃x  P(x) ∧ Q(x)
      "There is SOME x for which P(x) is true AND Q(x) is true"
       — using ∧ naturally captures "at least one x satisfies BOTH
          conditions together" — exactly what "SOME" needs.
```

## 5. Worked Examples

### 5.1 Universal Quantifier — Simple Case

> **"All apples belong to the fruit category."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `Apple(x)` | "x is an apple" (Apples) |
| `Fruit(x)` | "x belongs to the fruit category" |

**Key word "All"** → Universal Quantifier (`∀`), joined with **`→`**.

**Translated Mathematical Logic:**
```
∀x  Apple(x) → Fruit(x)
```
*(Read: "For every x, if x is an apple, then x belongs to the fruit category.")*

***

### 5.2 Universal Quantifier — Compound Predicate (with `∨` and `∧`)

> **"An apple or an orange is good for health and belongs to the fruit category."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `Apple(x)` | "Apples" |
| `Orange(x)` | "Oranges" |
| `Health(x)` | "x is good for health" |
| `Fruit(x)` | "x belongs to the fruit category" |
| `x` | "Either apple / orange" |

**Rule/Condition:** "... or ... [is] ... and ..." → Disjunction inside the "if" part, Conjunction inside the "then" part, whole thing still Universal (implicitly "any apple or orange, always").

**Translated Mathematical Logic:**
```
∀x  (Apple(x) ∨ Orange(x)) → (Health(x) ∧ Fruit(x))
```

This shows Predicate Logic isn't limited to one predicate per side — you can nest full propositional-logic expressions (`∨`, `∧`) **inside** each side of the quantified implication.

***

### 5.3 Existential Quantifier — Simple Case

> **"Some students are good at cricket."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `Student(x)` | Students (the Domain) |
| `Cricket(x)` | "x is good at cricket" |

**Key word "Some"** → Existential Quantifier (`∃`), joined with **`∧`**.

**Translated Mathematical Logic:**
```
∃x,  Student(x) ∧ Cricket(x)
```
*(Read: "There exists an x such that x is a student AND x is good at cricket.")*

***

### 5.4 Universal Quantifier — With Negation

> **"All birds cannot fly."**

**Breaking it down:**

| Symbol | Represents |
| :-- | :-- |
| `Birds(x)` | Birds |
| `Fly(x)` | "x can fly" |
| `¬Fly(x)` | "x cannot fly" |

**Translated Mathematical Logic:**
```
∀x  Birds(x) → ¬Fly(x)
```
*(Read: "For every x, if x is a bird, then x cannot fly." — Negation from Propositional Logic plugs directly into Predicate Logic the same way.)*

## 6. Predicate Logic Over a Restricted Domain

Sometimes `x` isn't just "any object" — it's restricted to a specific **domain** (set of allowed values), and the quantifier is checked **against that domain directly.**

### 6.1 Example — A Single Object (Constant)

> **"2 is an even number."**

Here `2` is a specific, fixed value (not a free variable) — this is a single **grounded** statement: `Even(2)` → simply True or False once evaluated directly, with no quantifier needed since there's no "for all" or "some" — it's about one specific object.

### 6.2 Example — Quantifying Over a Restricted Domain

> **"x is an even number and x is less than 10."**

**Predicate form:**
```
∀x ( Even(x) ∧ Less(x) )
```

**Domain restriction:** Suppose the domain of `x` is limited to `{0, 2, 4, 6, 8}` (i.e., we're only checking even numbers under 10).

```
CHECKING A UNIVERSAL QUANTIFIER OVER A DOMAIN

  Domain = {0, 2, 4, 6, 8}

  For ∀x (...) to be TRUE overall:
    EVERY single value in the domain must make the predicate TRUE.
    → It behaves like a big AND across the whole domain:
      P(0) ∧ P(2) ∧ P(4) ∧ P(6) ∧ P(8)
    → If even ONE value fails, the whole ∀ statement becomes FALSE.

  For ∃x (...) to be TRUE overall:
    AT LEAST ONE value in the domain must make the predicate TRUE.
    → It behaves like a big OR across the whole domain:
      P(0) ∨ P(2) ∨ P(4) ∨ P(6) ∨ P(8)
    → As soon as ONE value succeeds, the whole ∃ statement becomes TRUE.
```

This is the deeper reason behind the connective rule in Section 4.3: **`∀` naturally aligns with "must hold everywhere" (implication-style, all-or-nothing)**, while **`∃` naturally aligns with "just needs one hit" (conjunction-style, OR-across-domain in spirit)**.

## 7. Predicate Logic vs. Propositional Logic

| Aspect | **Propositional Logic** | **Predicate Logic** |
| :-- | :-- | :-- |
| **Deals With** | Fixed, whole statements (`P`, `q`, `r`) | Statements about **variables** ranging over a **domain** |
| **Can express "All/Some"?** |  No |  Yes — via `∀` (Universal) and `∃` (Existential) |
| **Building Blocks** | Atomic/compound statements + connectives | **Predicates** (e.g. `Apple(x)`) + **variables** + **quantifiers** + connectives |
| **Also Known As** | — | **First Order Logic** |
| **Relationship** | The base method | An **extension/optimized version** covering what Propositional Logic leaves out |
| **Example** | `P → (q ∨ ¬r)` | `∀x Apple(x) → Fruit(x)` |

***

## 8. Summary — Points to Remember

| # | Concept | Key Fact |
| :-- | :-- | :-- |
| (i) | **Universal Quantifier** | Represented by `∀` — covers **All/Each** category — uses **`→`** to relate the two sides |
| (ii) | **Existential Quantifier** | Represented by `∃` — covers **Some/Partial** category — uses **`∧`** to relate the two sides |
| (iii) | **Predicate** | A function like `P(x)` that becomes True/False once `x` is filled in with an actual object |
| (iv) | **Domain** | The full set of values `x` is allowed to take — quantifiers are always evaluated **relative to a domain** |
| (v) | **Nesting** | Propositional connectives (`¬, ∧, ∨`) can be freely combined **inside** a quantified statement, on either side of `∀x (...) → (...)` or `∃x (...) ∧ (...)` |
