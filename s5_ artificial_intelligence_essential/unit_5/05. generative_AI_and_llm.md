# Introduction to Generative AI, Large Language Models, and Future Trends in AI

## 1. What is "Generative AI"?

### 1.1 Simple Meaning

**Generative AI** is a branch of **Artificial Intelligence (AI)** that **creates new content** -- text, images, music, speech, video, computer code -- instead of only sorting or predicting things that already exist.

A **Large Language Model (LLM)** is the most famous kind of generative AI. It is a very large neural network that has learned from a huge amount of text, and it **writes text by predicting what piece of text should come next**, one piece after another.

A computer, at its core, only understands **numbers**. Human creations -- a paragraph, a painting, a song -- are rich, messy, and different every time. Generative AI is the system that **learns the patterns inside millions of such creations (as numbers), and then uses those patterns to produce brand-new ones**.

### 1.2 Everyday Analogy

Imagine a **student who has read an entire library** -- millions of books, articles, and letters. They do not memorize every page. Instead they **absorb how language works**: how stories open, how explanations are built, how a polite email sounds. Ask them, *"Write a thank-you note to my teacher,"* and they **write a new note in their own words**, using everything they absorbed. A generative model does the same, with one important difference: it has **no understanding in the human sense**, so it can sound sure of itself and still be wrong.

### 1.3 Traditional AI vs. Generative AI

| Feature | **Traditional (Predictive) AI** | **Generative AI** |
| :-- | :-- | :-- |
| **Main Question** | "What is this?" or "What will happen?" | "Create something new that fits this request" |
| **Output** | A label or a number | New content (text, image, audio, code, video) |
| **Example** | A spam filter says *Spam* or *Not Spam* | A model writes a complete email |
| **Example** | A model predicts a house price | A model draws a picture of a house |
| **Learned With** | Mostly supervised learning (see the Machine Learning note) | Large-scale learning from unlabeled data, then tuning with examples and feedback |

> **Note:** The two are not enemies. A chatbot can use a classifier to find the user's intent (see the Chatbots note) and a generative model to write the reply.

### 1.4 What Can Generative AI Create?

| Kind of Content | Example of a Request | Example of the Output |
| :-- | :-- | :-- |
| **Text** | *"Summarize this article in three lines"* | Three new sentences |
| **Code** | *"Write a function that sorts a list"* | A working piece of code |
| **Images** | *"A watercolor of a lighthouse at sunset"* | A new picture |
| **Audio and Speech** | *"Read this paragraph in a calm voice"* | A spoken recording |
| **Music** | *"A slow piano tune"* | A new short melody |
| **Video** | *"A paper boat sailing down a rain-filled street"* | A short new clip |
| **Designs and Data** | *"Suggest candidate molecules for this task"* | New designs for experts to test |

### 1.5 Where Is Generative AI Used?

| Application | What Generative AI Does |
| :-- | :-- |
| **Writing Help** | Drafts, rewrites, and translates emails, reports, and messages |
| **Coding Help** | Suggests code, explains errors, and writes tests |
| **Customer Support** | Powers chatbots that answer questions in natural language |
| **Education** | Explains topics step by step and creates practice questions |
| **Design and Media** | Produces images, logos, voice-overs, and video drafts |
| **Research and Business** | Summarizes long documents and searches company knowledge |
| **Accessibility** | Describes images aloud and turns speech into text and back |

### 1.6 A Short History

| Year | Milestone | Why It Matters |
| :-: | :-- | :-- |
| **2014** | **GANs** (Generative Adversarial Networks) | Showed that two competing networks can learn to produce realistic images |
| **2017** | **The Transformer** | A new design that handles language very well; it is the base of almost every modern LLM |
| **2018** | **GPT** and **BERT** | Showed the power of training on huge amounts of text first, then adapting |
| **2020** | **GPT-3** (175 billion parameters) | Showed that a very large model can do many tasks from a simple text request |
| **2022** | **Stable Diffusion** and **ChatGPT** | Brought diffusion-based image generation and LLM chat to millions of everyday users |
| **2024** | **Reasoning models** appear | Models that work through a problem in steps before answering |

## 2. The Big Picture -- How Generative Models Create

Every generative model works in **two phases**: it is **trained once**, and then **used many times**.

```
THE TWO PHASES OF A GENERATIVE MODEL

 PHASE 1: TRAINING  (done once; needs huge data and computing power)

   HUGE COLLECTION OF EXAMPLES  (text, images, audio, code)
              |
              v
   [ LEARNING ]  adjust billions of internal numbers (PARAMETERS)
                 until the model gets good at the task
              |
              v
   TRAINED MODEL  (the learned patterns, saved as a very large set of numbers)


 PHASE 2: GENERATION  (done every time someone uses the model)

   PROMPT  (a request written by the user)
              |
              v
   [ TRAINED MODEL ]  uses the patterns it learned
              |
              v
   NEW OUTPUT  (text, image, audio, ...)  produced fresh each time
```

| Phase | Input | Output | How Often |
| :-- | :-- | :-- | :-- |
| **1. Training** | A huge collection of examples | A trained model (the parameters) | Once, or once in a long while |
| **2. Generation** (also called **inference**) | A prompt | New content | Every time someone uses the model |

### 2.1 The Main Families of Generative Models

```
                        +---------------------------+
                        | GENERATIVE AI MODEL TYPES |
                        +-------------+-------------+
                                      |
            +-------------------------+-------------------------+
            |                         |                         |
            v                         v                         v
 +---------------------+   +---------------------+   +---------------------+
 |  LLM (TRANSFORMER)  |   |   DIFFUSION MODEL   |   |         GAN         |
 +---------------------+   +---------------------+   +---------------------+
     writes text one        starts from noise and       a forger competes
     piece at a time        cleans it up in steps      against a detective
```

| Model Type | How It Creates | Everyday Picture | Best Known For |
| :-- | :-- | :-- | :-- |
| **LLM (Transformer)** | Predicts the next piece of text, over and over | Writing a story one word at a time while re-reading everything so far | Text and code, chat assistants |
| **Diffusion Model** | Starts from random noise and removes it step by step, steered by the prompt | A blurry static screen slowly sharpening into a picture | Images, and increasingly audio and video |
| **GAN** | A *generator* makes fakes while a *discriminator* tries to spot them; both improve | A forger competing with a detective | Early realistic image generation |

> **Note:** There are other types too, such as **VAEs** (Variational Autoencoders). This note focuses on the three above because they explain most of today's tools.

## 3. Large Language Models (LLMs)

### 3.1 Simple Meaning

A **Large Language Model** is a neural network, built on the **Transformer** design, that has learned from an enormous amount of text. Its basic skill is simple: **given some text, give a probability to every possible next piece of text**. To write a whole answer, it repeats this step again and again, adding one piece at a time.

### 3.2 Everyday Analogy

Think of the **autocomplete on a phone keyboard** that suggests the next word. An LLM is that idea scaled up enormously: it has read far more text, and it looks at the **whole conversation so far**, not just the last word or two.

### 3.3 Key Terms

| Term | Meaning | Example |
| :-- | :-- | :-- |
| **Token** | A small piece of text the model works with: a word, part of a word, or a symbol | *"unhappiness"* might be split into *un*, *happi*, *ness* |
| **Parameter** | One learned number inside the model; training adjusts them | GPT-3 had 175 billion; today's biggest models are far larger or are not publicly stated |
| **Prompt** | The text you give the model (your request and any context) | *"Explain photosynthesis to a 10-year-old"* |
| **Embedding** | A list of numbers that represents the meaning of a token | The tokens *king* and *queen* get similar lists |
| **Context Window** | The most text (in tokens) the model can read at one time | Varies a lot between models, from a few thousand tokens to over a million in some |
| **Pre-training** | The first, large learning phase on huge amounts of text | Learning to predict the next token |
| **Fine-tuning** | Extra training on smaller, specific data | Training a model on a company's support conversations |
| **Inference** | Using the trained model to produce an answer | Every time you press Send |
| **Temperature** | A setting that controls how adventurous the word choice is | Low = safe and repeatable; high = varied |
| **Hallucination** | A fluent but false statement written by the model | An invented book title |

### 3.4 From Text to the Next Word

One round of generation passes through a short **pipeline**:

```
FROM TEXT TO THE NEXT WORD (ONE STEP OF GENERATION)

   TEXT         "The cat sat on the"
        |
        v   1. TOKENIZE       cut the text into tokens
   TOKENS       [The] [ cat] [ sat] [ on] [ the]
        |
        v   2. LOOK UP        each token becomes an ID number
   IDS          [ 464, 3797, 3332, 319, 262 ]      (made-up numbers)
        |
        v   3. EMBED          each ID becomes a list of numbers (a vector)
   VECTORS      5 vectors, each holding hundreds or thousands of numbers
        |
        v   4. TRANSFORMER LAYERS (the same recipe, repeated many times)
                 attention     : every token looks at the other tokens
                                 and decides which ones matter
                 feed-forward  : further processes each token
        |
        v   5. SCORE          a probability for every token the model knows
   PROBABILITIES   mat 45%, sofa 20%, floor 15%, roof 5%, ...
        |
        v   6. CHOOSE         pick one token (with a little randomness)
   NEW TOKEN    " mat"
        |
        v   7. APPEND AND REPEAT
   "The cat sat on the mat"   -> predict again
```

**How big is a token?** As a rough rule for English, **1 token is about three-quarters of a word** (so 100 tokens is about 75 words). Text in some other languages often needs **more tokens per word**.

### 3.5 Attention -- How the Model Knows What *"it"* Means

The key idea inside the Transformer is **attention**: when the model processes a word, it **looks back at the other words and gives each a weight** showing how much it matters right now.

Take the sentence *"The animal did not cross the street because it was too tired."* What does *"it"* refer to -- the animal or the street? A person knows at once: **the animal** (a street cannot be tired). Attention lets the model work this out too. The numbers below are an illustrative example:

```
The animal did not cross the street because it was too tired.
When the model processes the word "it", how much does it look at each word?

animal           60%  ########################
street           15%  ######
tired            10%  ####
cross             5%  ##
other words      10%  ####

(each # = 2.5%)
```

The weights add up to 100%. Most of the attention goes to **animal**, so the model reads *"it"* as the animal. In a real model there are **many attention "heads"** at once, each looking for a different kind of relationship, and this happens in **every layer**.

### 3.6 How an LLM Is Trained

```
HOW MANY MODERN CHATBOT LLMs ARE TRAINED

   [ STAGE A ]  PRE-TRAINING
                Read a huge amount of text and learn to predict
                the next token
              |
              v
   [ STAGE B ]  INSTRUCTION TUNING
                Learn from example requests paired with good answers,
                so the model follows instructions instead of just
                continuing the text
              |
              v
   [ STAGE C ]  FEEDBACK TUNING
                People compare answers; the model is nudged toward the
                answers that people prefer
              |
              v
   A MODEL THAT CAN FOLLOW REQUESTS IN A CONVERSATION
```

| Stage | Learns From | What the Model Gets Good At | Everyday Picture |
| :-- | :-- | :-- | :-- |
| **A. Pre-training** | A huge amount of text (for the biggest models, trillions of tokens) | Grammar, facts, and patterns of language | A student reading a whole library |
| **B. Instruction Tuning** | Many examples of requests with good answers | Following instructions and answering in a helpful format | An apprenticeship with a teacher |
| **C. Feedback Tuning** | People's choices between answers (*RLHF*, reinforcement learning from human feedback, is the best-known method) | Giving answers that people find helpful and safe | A reviewer marking the student's drafts |

> **Note:** Training methods keep changing, and different companies use different recipes. The three stages above are the clearest way to understand the **overall idea**. Training the largest models needs enormous computing power and money, which is why only a few organizations do it from scratch.

### 3.7 Choosing the Next Word -- Temperature

The model gives every possible next token a probability, but it does not always take the top one. It **chooses among the likely tokens with some randomness**, and the **temperature** setting controls how much. These numbers are illustrative, for the text *"The cat sat on the ____"*:

**Low temperature (safe and repeatable):**

```
mat              80%  ################################
sofa             10%  ####
floor             5%  ##
roof              0%
other words       5%  ##
```

**Medium temperature (balanced):**

```
mat              45%  ##################
sofa             20%  ########
floor            15%  ######
roof              5%  ##
other words      15%  ######
```

**High temperature (varied and surprising):**

```
mat              30%  ############
sofa             25%  ##########
floor            20%  ########
roof             10%  ####
other words      15%  ######
```

(each # = 2.5%)

| Temperature | Behavior | Good For | Risk |
| :-- | :-- | :-- | :-- |
| **Low** | Almost always picks the most likely token | Facts, summaries, code | Repetitive; can sound dull |
| **High** | Willing to pick less likely tokens | Stories, brainstorming, slogans | More mistakes and odd wording |

This randomness is why asking the same question twice can give **differently worded answers**.

### 3.8 Prompting -- How to Ask Well

A **prompt** is your instruction to the model. Better prompts usually give better answers, because the model can only work with what you wrote.

| Technique | What to Do | Example |
| :-- | :-- | :-- |
| **Be Specific** | Say exactly what you want, for whom, and how long | *"Explain photosynthesis to a 10-year-old in two sentences."* |
| **Give Context** | Include the background the model cannot guess | *"I am a Class 9 student preparing for a science test."* |
| **Set a Role** | Say who the model should act as | *"Act as a patient maths teacher."* |
| **Show Examples** (*few-shot*) | Give one or more samples of the pattern you want | See the prompt below |
| **Ask for Steps** | Ask it to work through the problem step by step | *"Solve this and show each step."* |
| **Choose the Format** | Say how the answer should look | *"Answer as a table with two columns."* |
| **Iterate** | Look at the answer, then refine the request | *"Make it shorter and simpler."* |

A **few-shot prompt** teaches the pattern with examples:

```
Classify the review as Positive or Negative.

Review: "Loved the food"                    -> Positive
Review: "Waited an hour, cold pizza"        -> Negative
Review: "Great service and tasty paneer"    ->
```

The model continues the pattern and writes **Positive**. A request with **no examples** is called **zero-shot**.

### 3.9 The Context Window -- The Model's Working Memory

The model can only read a limited amount of text at once: the **context window**. Everything -- your instructions, the earlier messages, any documents you paste, and the reply being written -- must fit inside it. If a conversation grows too long, the oldest parts may be shortened or dropped, and the model can then **forget early details**. This is the same limit described in the Chatbots note.

## 4. Image and Multimodal Generation

### 4.1 Simple Meaning

Image generators are mostly built on **diffusion models**. A diffusion model learns to **remove noise from a picture**. To make a new picture, it starts from **pure random noise** and **cleans it up step by step**, guided by the text prompt, until a picture appears.

### 4.2 Everyday Analogy

Picture a **television showing only static**. Someone slowly turns a focus knob, and a faint shape appears, then a clearer one, and finally a sharp picture -- the one you asked for. Each small turn removes a little noise.

### 4.3 How a Diffusion Model Learns and Creates

| Phase | What Happens |
| :-- | :-- |
| **Training** | Take many real pictures. Add a little noise to each, again and again, until only noise is left. The model learns to **undo one small step of noise** |
| **Creating** | Start from pure random noise. Repeatedly **remove a little noise**, while the text prompt (turned into numbers) **steers** the result toward what was asked |

Here is a **toy picture** of the idea, for the prompt *"a small house"*. Each step removes some noise:

```
Step 0        Step 1        Step 2        Step 3        Step 4
pure noise    a hint        taking shape  almost clear  finished

:%%:#*#,      ; */%. ;        :/*  :         /\            /\
,,%+.;*;       ;/ +%          /  :          /  %          /  \
+;::;**#      ;*%,+_;:      #+#_._:        ;__,_,        /____\
;#%+#:,:       |,%]*;%       | #]%;        | #] |        | [] |
.#::;:.;      *|__;##;      :|__,_|.       |____|        |____|
%#:.;+**      ,#%+=;,*      ==:%=;:%      ==%====*      ========
```

> **Note:** This drawing is only a toy to show the idea. A real image model works on millions of pixels (or on a compressed form of the picture) and usually uses many steps, often dozens or more.

### 4.4 GANs -- A Forger and a Detective

A **GAN** has two networks that **compete and improve together**:

```
   random noise --> [ GENERATOR ] --> fake image --+
                                                   |
                                                   v
                                           [ DISCRIMINATOR ] --> "real or fake?"
                                                   ^
                                                   |
   real photos (training data) --------------------+
```

- The **generator** turns random noise into a fake image.
- The **discriminator** looks at real photos and fakes and says "real" or "fake".
- When the discriminator catches a fake, the generator **learns to do better**. When the generator fools the discriminator, the discriminator **learns to look harder**.

After much practice, the fakes become very realistic. GANs can be tricky to train, and many newer image tools use diffusion instead.

### 4.5 Multimodal Models

A **multimodal model** can work with **more than one kind of data** at once -- for example text, images, and audio -- inside one system.

| What You Give It | What You Ask | What It Returns |
| :-- | :-- | :-- |
| A photo of a plant | *"What is wrong with this leaf?"* | A text answer |
| A chart image | *"Summarize this graph"* | A text summary |
| Text | *"Draw a red bicycle"* | An image |
| Your voice | *"What is the weather like?"* | A spoken answer (see the Speech Recognition and Chatbots notes) |

### 4.6 An Important Warning -- Realistic Does Not Mean Real

Generated images, voices, and videos can look and sound **convincingly real**. This helps creators, but it also makes **fake content (deepfakes)** easier to produce. Small details in generated images, such as text inside the picture or fine details of hands, can still come out wrong. Always check where important images and audio came from.

## 5. Making LLMs More Useful and Reliable

A plain LLM has limits: its knowledge stops at its training date, it can invent facts, and it cannot act on the world by itself. These techniques address that:

| Technique | What It Does | Example |
| :-- | :-- | :-- |
| **Better Prompting** | Gives clearer instructions and examples | The few-shot prompt in Section 3.8 |
| **RAG** (Retrieval-Augmented Generation) | Looks up real documents first, then lets the model answer from them | A bot answers a refund question using the company's policy pages (see the Chatbots note) |
| **Tools** (also called function calling) | Lets the model ask a program to do something and use the result | Calling a calculator, a search engine, or a calendar |
| **Fine-tuning** | Trains the model further on specific data | A model tuned on a hospital's writing style |
| **Guardrails** | Rules that check inputs and outputs for unsafe or off-topic content | Blocking a request that is outside the bot's job |
| **Human Review** | A person checks important outputs | A lawyer reads an AI-drafted contract |

A sensible order to try them: **prompting first, then RAG or tools, and fine-tuning last**, because the earlier ones are cheaper and easier to change.

## 6. Full Worked Example -- One Prompt, Start to Finish

**The prompt** (typed by a student):

```
"Explain photosynthesis to a 10-year-old in two sentences."
```

### 6.1 The Journey, Step by Step

```
USER PROMPT
   "Explain photosynthesis to a 10-year-old in two sentences."
              |
              v   Step 1: TOKENIZE  (the split below is illustrative)
   [Explain] [ photo] [synthesis] [ to] [ a] [ 10] [-year] [-old] [ in] [ two] [ sentences] [.]
                                                              (12 tokens)
              |
              v   Step 2: TURN TOKENS INTO NUMBERS (IDs, then embeddings)
   12 tokens -> 12 vectors
              |
              v   Step 3: TRANSFORMER LAYERS (attention links the words:
                  "10-year-old" and "two sentences" shape the style and length)
              |
              v   Step 4: SCORE THE NEXT TOKEN (one probability per possible token)
              |
              v   Step 5: CHOOSE ONE TOKEN, ADD IT TO THE TEXT
              |
              v   Step 6: REPEAT STEPS 2 TO 5, one token at a time,
                  until the model produces an "end of reply" token
              |
              v   Step 7: JOIN THE TOKENS INTO TEXT
   The reply
```

### 6.2 The First Three Tokens

**Token 1.** The model scores every possible first token (illustrative numbers):

```
Plants           40%  ################
Photosynthesis   30%  ############
It               10%  ####
Imagine          10%  ####
other words      10%  ####

(each # = 2.5%)
```

"Plants" has the highest probability (40%), so it is the most likely choice, and here the model picks **"Plants"**. (It could have picked a less likely one, which is why answers can vary.)

**Token 2.** The text so far is the prompt plus "Plants":

| Next Token | Probability |
| :-- | :-: |
| ` make` | 0.55 |
| ` use` | 0.25 |
| ` are` | 0.10 |
| all others together | 0.10 |

The model picks **" make"**.

**Token 3.** The text so far is the prompt plus "Plants make":

| Next Token | Probability |
| :-- | :-: |
| ` their` | 0.60 |
| ` food` | 0.20 |
| ` energy` | 0.10 |
| all others together | 0.10 |

The model picks **" their"**, and continues in the same way, token after token.

### 6.3 How Many Rounds?

The finished reply has **39 words**. At about three-quarters of a word per token, that is **roughly 50 tokens**. The model therefore ran this loop about **50 times** -- once per token. It does not plan the whole answer first and then print it; it builds the answer **one piece at a time**, each piece depending on everything before it.

### 6.4 The Final Reply

```
Plants make their own food using sunlight, water, and a gas from the air
called carbon dioxide. Their green leaves catch the sunlight and turn these
ingredients into sugar for energy, and they release oxygen for us to breathe.
```

Check against the request: the reply is **two sentences**, in **simple words** suitable for a 10-year-old, and the science is correct.

### 6.5 What Each Step Did

| Step | Action | Why It Was Needed | Result |
| :-: | :-- | :-- | :-- |
| **1** | Tokenize | The model works with tokens, not raw sentences | **12 tokens** |
| **2** | Embed | Numbers can be processed; text cannot | **12 vectors** |
| **3** | Transformer layers (attention) | Work out how the words relate, such as who the audience is | **Context-aware vectors** |
| **4** | Score | Decide how likely each next token is | **A probability for every token** |
| **5** | Choose | A reply needs one real token each time | **One token, such as "Plants"** |
| **6** | Repeat | A reply is many tokens long | **About 50 rounds** |
| **7** | Join | The user needs readable text | **The two-sentence reply** |

### 6.6 What a Clearer Prompt Changes

The same model, given different prompts, gives very different results:

| Prompt | What You Would Likely Get | Why |
| :-- | :-- | :-- |
| *"photosynthesis"* | A long, general textbook-style explanation | The model has to guess the audience, length, and goal |
| *"Explain photosynthesis."* | A medium-length explanation at a general level | The goal is clear, but the audience and length are not |
| *"Explain photosynthesis to a 10-year-old in two sentences."* | A short, simple, two-sentence answer | The audience, length, and style are all stated |

### 6.7 When It Goes Wrong -- A Hallucination

Suppose the student then asks: *"Give me the exact title of a research paper about photosynthesis in desert plants."* A model with no way to search may **write a title that sounds perfect but does not exist**, because it is built to produce **likely-sounding text**, not to look things up. The fixes are the ones from Section 5: let the model **search real sources (RAG or tools)**, and **check any citation yourself**.

### 6.8 The Final Form

The student's request started as **plain words**. After the pipeline it became:

```
Written reply :  a two-sentence, kid-friendly explanation of photosynthesis
```

Plain text again -- which, like any text, can be cleaned, split into tokens, and used by other NLP systems, as described in the NLP note.

## 7. Risks, Limits, and Responsible Use

| Risk or Limit | Explanation | Example |
| :-- | :-- | :-- |
| **Hallucination** | The model writes likely text, not checked facts | A made-up citation or statistic |
| **Outdated Knowledge** | Knowledge stops at the training date unless the model can search | A question about a recent event |
| **Bias** | The model can copy unfair patterns from its training data | Stereotyped descriptions of groups of people |
| **Privacy** | Anything typed in may be stored or seen, depending on the service | A user pastes a phone number or private document |
| **Security** | Tricky text can try to make a model ignore its instructions (*prompt injection*) | A web page hides a command for an AI assistant |
| **Copyright and Ownership** | There are ongoing legal and ethical debates about training data and about who owns AI-made work | An image that closely imitates an artist's style |
| **Deepfakes and Misinformation** | Realistic fake images, audio, and video are easy to make | A fake voice message |
| **Over-reliance** | Trusting answers without thinking can weaken your own skills | Copying an answer to homework without understanding it |
| **Cost and Energy** | Training and running large models uses a lot of computing power and electricity | Large data centres |
| **No Real Understanding** | The model manipulates patterns of text; it does not have human understanding or feelings | A caring-sounding reply is still produced by software |

**Good habits for using generative AI:**

- **Check important facts** against a trusted source.
- **Do not paste private or secret information** unless you know how the service handles it.
- **Say when content was made with AI**, where honesty matters (school work, news, ads).
- **Keep a human in charge** of decisions about health, money, law, and safety.
- **Use it to learn**, not only to get answers: try to understand the answer.

## 8. Future Trends in Artificial Intelligence

### 8.1 Simple Meaning

**Future trends in AI** are the **directions in which AI seems to be moving**, based on what researchers, companies, and governments are doing today. They are **signals, not promises**: nobody can know exactly what will happen.

### 8.2 Everyday Analogy

Think of a **weather forecast**. Meteorologists read clouds, pressure, and wind to say, *"Rain is likely tomorrow."* They are often right, sometimes wrong, and they update the forecast as new data arrives. Looking at AI's future works the same way: we read the signals we have, and we expect to **revise the forecast** as things change.

> **Note:** This section describes the situation as of **October 2026**. Product names, dates, and rules in this area change quickly. The **ideas** will age far better than the specific details.

### 8.3 Where Are We on the Road?

| Level | Meaning | Status |
| :-- | :-- | :-- |
| **Today's AI** | Powerful tools that are very good at many tasks (even broad ones such as writing and coding) but are still limited, can be wrong, and need human oversight | **Exists** |
| **AGI** (Artificial General Intelligence) | A hypothetical AI that can learn and do most intellectual tasks as flexibly as a person | **Not achieved**; there is no agreed definition and no agreed timeline |
| **ASI** (Artificial Superintelligence) | A hypothetical AI far beyond human ability | **Hypothetical** |

```
TODAY  ---->  AGI (hypothetical)  ---->  ASI (hypothetical)
```

Experts **disagree strongly** about whether, when, and how the later steps might happen. This note therefore focuses on the **trends we can already see**, not on guesses about the far future.

### 8.4 Key Trends to Watch

| # | Trend | What Is Changing | Example |
| :-: | :-- | :-- | :-- |
| **1** | **AI Agents** | From answering questions to **carrying out multi-step tasks** using tools | An assistant that researches a topic, writes a summary, and files it |
| **2** | **Multimodal by Default** | One model handles text, images, audio, and video together | A model that reads a screenshot and answers aloud |
| **3** | **Reasoning Models** | Models that spend extra effort **working through a problem step by step** before answering | Better at maths, coding, and planning, but slower and costlier per answer |
| **4** | **Smaller, Efficient, On-Device Models** | Compact models that run on phones and laptops, and small models specialized for one field | Private voice typing without sending audio away |
| **5** | **Open and Closed Models** | Some models' parameters can be downloaded and adapted (*open-weight*); others are used only through a service | Schools running an open model on their own computers |
| **6** | **Connected Tools and Standards** | Common ways to plug models into tools and company data (one example is MCP, the Model Context Protocol) | One tool connection that many assistants can reuse |
| **7** | **Physical AI and Robotics** | Models that see the world and control machines | A warehouse robot that follows spoken instructions |
| **8** | **AI for Science and Health** | AI helps discover and test ideas in biology, medicine, weather, and materials | AlphaFold predicts protein shapes; its creators shared the 2024 Nobel Prize in Chemistry |
| **9** | **Personalization and Memory** | Assistants that remember your preferences, with controls you can adjust | A study helper that remembers which topics you find hard |
| **10** | **Evaluation and Safety** | More testing of what models can and cannot do safely, and research into how they work inside | Tests that check for harmful or false answers |
| **11** | **Regulation and Standards** | Governments write rules about risky uses of AI | The EU AI Act (Section 8.7) |
| **12** | **Efficiency and Energy** | Pressure to make training and running models use less power | More efficient chips and smaller models |

> **Note:** Trend 8 needs a caution: a promising AI result in a lab still has to be **checked by experts and tested** (for example in clinical trials) before it can be relied on.

### 8.5 AI Agents in More Detail

An **AI agent** is a system built around a model that **works toward a goal over several steps**. It keeps going around a loop: **plan, act, observe, check**.

```
   1. GOAL (from the user)
        |
        v
   2. PLAN the next step <------------------+
        |                                   |
        v                                   |
   3. ACT (use a tool)                      |
        |                                   |
        v                                   |
   4. OBSERVE the result                    |
        |                                   |
        v                                   |
   5. CHECK: is the goal done? ---- no -----+
        | yes
        v
   6. REPORT to the user
```

| Part of the Loop | What the Agent Does |
| :-- | :-- |
| **Goal** | Receives what the user wants |
| **Plan** | Decides the next small step |
| **Act** | Uses a tool, such as a search, a calculator, or a calendar |
| **Observe** | Reads what the tool returned |
| **Check** | Decides whether the goal is met; if not, goes around the loop again |
| **Report** | Tells the user the result |

> **Note:** Agents are exciting but still **not fully reliable**. A mistake in one step can carry into the next. That is why good agents **ask for confirmation before actions that are hard to undo**, such as spending money or deleting files.

### 8.6 Worked Example -- A Day With an AI Agent

**The goal** (typed by a user):

```
"Find the latest morning train next Friday that reaches the city by 11:00 am,
 and put it in my calendar."
```

The agent has two tools: a **timetable search** and a **calendar**. (The train times below are made up for the example.)

| Round | Plan | Act | Observe | Check |
| :-: | :-- | :-- | :-- | :-- |
| **1** | I need the list of morning trains | Search the timetable for next Friday | Three trains: **06:30** (arrives 09:30), **08:15** (arrives 11:00), **09:40** (arrives 12:10) | Not done: no train chosen yet |
| **2** | Keep trains that arrive by 11:00, then take the latest departure | Compare the three times (no tool needed) | 06:30 qualifies; 08:15 qualifies; 09:40 does not. The latest that qualifies is **08:15** | Not done: nothing is in the calendar |
| **3** | Add the 08:15 train to the calendar | Create a calendar event | Event created | **Done** |

```
REPORT TO THE USER
   "Done. I added the 08:15 train (arrives 11:00) to your calendar for Friday."
```

Notice what the agent did **not** do: it did not buy a ticket, because the goal only asked for a calendar entry. If the goal had included buying, a careful agent would have **read the details back and waited for a clear "yes"**, as in the Chatbots note.

### 8.7 Governance -- Rules for AI

Governments are writing rules so that AI is useful and safe. The best-known example is the **EU AI Act**, which is **risk-based**: the riskier the use, the stricter the rules.

| Risk Level | What It Means | Example |
| :-- | :-- | :-- |
| **Unacceptable** | Uses that are banned | Scoring people's social behavior to treat them differently |
| **High-Risk** | Allowed, but with strict duties such as testing, documentation, and human oversight | AI used in hiring, credit decisions, or education |
| **Transparency** | Users must be told they are dealing with AI, and some AI-made content must be labeled | A chatbot, or a realistic AI-made video |
| **Minimal** | Few or no extra rules | A spam filter, or AI in a video game |

As reported in mid-2026, the EU agreed to **delay** the main high-risk rules, from **2 August 2026 to 2 December 2027** (and to **2 August 2028** for AI built into regulated products such as medical devices). The overall direction did not change, and some other rules, including those for general-purpose models, stayed on their original course. Other countries are choosing **different approaches**, and rules are still developing. For anything where the law matters, **check the official source for the current dates**.

### 8.8 Jobs and Skills

AI changes **tasks** within jobs more than it removes whole jobs overnight, though the effects vary by field and are debated.

| AI Tends to Help With | People Remain Important For |
| :-- | :-- |
| Drafting, summarizing, and translating | Deciding what is worth saying, and being accountable for it |
| Writing first versions of code | Understanding the problem and checking the result |
| Finding patterns in large data | Asking the right questions and using the answers wisely |
| Answering routine questions | Handling unusual, sensitive, and emotional situations |

**Skills that stay valuable if you are learning AI:**

| Skill | Why It Helps |
| :-- | :-- |
| **Basic maths and statistics** | They explain how models learn and how to judge results |
| **Programming** | It lets you build, test, and connect AI tools |
| **Machine learning and NLP fundamentals** | These notes: the ideas under every new tool |
| **Working with data** | Good data decides whether a model is good |
| **Prompting and checking answers** | You get more from AI and avoid its mistakes |
| **Ethics and responsibility** | Someone must decide what AI should and should not be used for |
| **Knowledge of one field** (health, law, farming, teaching, ...) | AI is most useful when someone understands the real problem |

### 8.9 What Will Probably Stay the Same

Even as tools change, some things are likely to hold:

- **Data quality matters.** Poor data gives poor results.
- **People stay responsible.** An organization cannot blame the software.
- **Testing never ends.** A model must be checked on new, unseen situations.
- **Fundamentals last.** The ideas in the Machine Learning, NLP, Speech, and Chatbot notes underlie new tools, even when the names change.
- **Trust must be earned.** Honest limits, clear labels, and a human fallback build trust.

### 8.10 An Important Warning -- Predictions Can Be Wrong

Forecasts about AI have been wrong in **both directions**: some changes arrived faster than almost anyone expected, while other promised breakthroughs took much longer. Treat every trend in this section as a **direction to watch**, not a certainty, and look for **evidence** (tests, results, real use) rather than hype or fear.

## 9. Summary

| Concept | One-Line Summary |
| :-- | :-- |
| **Generative AI** | AI that creates new content: text, images, audio, code, and video |
| **Traditional vs Generative AI** | Traditional AI labels or predicts; generative AI creates |
| **The Two Phases** | Train once on huge data, then generate every time someone gives a prompt |
| **LLM** | A large Transformer model that writes text by predicting the next token, one at a time |
| **Token** | A small piece of text; about three-quarters of an English word |
| **Parameter** | One learned number inside the model |
| **Attention** | Lets the model weigh which earlier words matter for the current word |
| **Pre-training, Instruction Tuning, Feedback Tuning** | The three main training stages of a chat LLM |
| **Temperature** | Controls how adventurous the token choice is; low is safe, high is varied |
| **Prompt** | Your instruction to the model; clear, specific prompts give better answers |
| **Context Window** | The limited amount of text the model can read at once |
| **Diffusion Model** | Makes images by removing noise step by step, guided by the prompt |
| **GAN** | A generator and a discriminator that compete and improve together |
| **Multimodal Model** | One model that handles several kinds of data, such as text, images, and audio |
| **RAG and Tools** | Look up real information or call programs so the model is more accurate and useful |
| **Hallucination** | A fluent but false statement; check important facts |
| **Responsible Use** | Check facts, protect privacy, label AI content, and keep humans in charge |
| **AI Agent** | A system that plans, acts with tools, observes, and checks until a goal is met |
| **AGI** | A hypothetical human-level, general AI; not achieved, and experts disagree on timing |
| **Key Trends** | Agents, multimodal models, reasoning models, smaller on-device models, physical AI, AI for science, safety, and regulation |
| **EU AI Act** | A risk-based law: the riskier the use, the stricter the rules |
| **Key Limitation** | Models can be wrong, biased, or outdated, and predictions about AI's future are uncertain |
