# 23. File Uploads & External Services

> **Goal:** Upload files from a Next.js app to an external storage provider (Cloudinary) using Server Actions — single file, multiple files, validation, and security.
>
> **Builds on:** Server/Client Components, Server Actions, `FormData`, and basic Node.js backend concepts.
>
> **Important:** The database stores file **metadata** (URL, public ID, size). Cloudinary stores the **actual file**.

---

## 1. File Upload Flow

```text
Browser
   ↓
Select file(s)
   ↓
FormData
   ↓
Server Action
   ↓
Validate (size, type, count)
   ↓
Cloudinary (external service)
   ↓
Save secure_url + public_id in database
```

Common use cases:

```text
Profile picture       → single image
Product gallery       → multiple images
Document attachment   → PDF / file
```

---

## 2. `FormData` and Server Actions

A file input sends a `File` object inside `FormData` when the form is submitted.

**Single file** — one input, one `formData.get("image")`:

```tsx
<input type="file" name="image" accept="image/*" />
```

**Multiple files** — add the `multiple` attribute, read with `formData.getAll("images")`:

```tsx
<input type="file" name="images" accept="image/*" multiple />
```

Server Action receives the `FormData` automatically when used as a form `action`:

```ts
"use server";

export async function uploadImage(formData: FormData) {
  const file = formData.get("image");

  if (!(file instanceof File)) {
    throw new Error("Image is required");
  }

  // file.name, file.size, file.type are available here
}
```

Route Handlers can also read uploads via `await request.formData()`, but Server Actions are the simplest fit when the upload comes from a Next.js form.

## 3. Server-Side Validation

Never trust the browser. Always validate on the server before sending to Cloudinary.

| Check | Why |
| ----- | --- |
| File exists | Empty submission / tampered form |
| File size | Prevent huge uploads (Server Action body limit defaults to ~1 MB) |
| MIME type | `accept="image/png"` on the client is not security |
| File count | Limit multi-upload abuse |
| Auth | Only logged-in users should upload |

Example validation helper:

```ts
const MAX_SIZE = 5 * 1024 * 1024; // 5 MB
const ALLOWED_TYPES = ["image/jpeg", "image/png", "image/webp"];

function validateImage(file: File) {
  if (file.size > MAX_SIZE) {
    throw new Error("File must be 5 MB or smaller");
  }
  if (!ALLOWED_TYPES.includes(file.type)) {
    throw new Error("Only JPEG, PNG, and WebP images are allowed");
  }
}
```

For files larger than 1 MB, increase the Server Action body limit in `next.config.ts`:

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  experimental: {
    serverActions: {
      bodySizeLimit: "10mb",
    },
  },
};

export default nextConfig;
```

## 4. Why Cloudinary?

Cloudinary is a hosted media platform — upload, store, transform, and deliver images and videos via URL.

```text
Next.js Server Action
        ↓
Cloudinary Node.js SDK
        ↓
Cloudinary CDN
        ↓
https://res.cloudinary.com/.../image.jpg
```

Benefits over storing files on the app server's disk:

```text
✓ Works in serverless / multi-instance deployments
✓ Built-in image transforms (resize, crop, format)
✓ CDN delivery
✓ No local /uploads folder to manage
```

## 5. Setup

### 5.1 Install and Environment Variables

```bash
npm install cloudinary
```

Create a Cloudinary account and add credentials to `.env.local` (server-only — never use `NEXT_PUBLIC_` for secrets):

```env
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
```

### 5.2 Cloudinary Client — `lib/cloudinary.ts`

Configure the SDK once and reuse it across Server Actions:

```ts
import { v2 as cloudinary } from "cloudinary";

cloudinary.config({
  cloud_name: process.env.CLOUDINARY_CLOUD_NAME,
  api_key: process.env.CLOUDINARY_API_KEY,
  api_secret: process.env.CLOUDINARY_API_SECRET,
  secure: true,
});

export default cloudinary;
```

### 5.3 Upload Helper — `lib/upload-to-cloudinary.ts`

Cloudinary's `upload_stream` is callback-based. Wrap it in a `Promise` and pass a Node.js `Buffer`:

```ts
import type { UploadApiResponse } from "cloudinary";
import cloudinary from "@/lib/cloudinary";

export async function uploadToCloudinary(
  file: File,
  folder: string
): Promise<UploadApiResponse> {
  const arrayBuffer = await file.arrayBuffer();
  const buffer = Buffer.from(arrayBuffer);

  return new Promise((resolve, reject) => {
    cloudinary.uploader
      .upload_stream(
        {
          folder, // e.g. "shop/products"
          resource_type: "auto", // detect image / video / raw
        },
        (error, result) => {
          if (error || !result) {
            reject(error ?? new Error("Upload failed"));
            return;
          }
          resolve(result);
        }
      )
      .end(buffer);
  });
}
```

## 7. Single File Upload

### 7.1 Server Action — `app/products/actions.ts`

```ts
"use server";

import { revalidatePath } from "next/cache";
import { uploadToCloudinary } from "@/lib/upload-to-cloudinary";

const MAX_SIZE = 5 * 1024 * 1024;
const ALLOWED_TYPES = ["image/jpeg", "image/png", "image/webp"];

export async function uploadSingleImage(formData: FormData) {
  const file = formData.get("image");

  if (!(file instanceof File)) {
    throw new Error("Image is required");
  }

  // Server-side validation — never skip this
  if (file.size > MAX_SIZE) {
    throw new Error("Image must be 5 MB or smaller");
  }
  if (!ALLOWED_TYPES.includes(file.type)) {
    throw new Error("Only JPEG, PNG, and WebP are allowed");
  }

  // Upload to Cloudinary external service
  const result = await uploadToCloudinary(file, "shop/products");

  // Save metadata in your database (example shape):
  // await db.productImage.create({
  //   url: result.secure_url,
  //   publicId: result.public_id,
  //   width: result.width,
  //   height: result.height,
  //   bytes: result.bytes,
  // });

  revalidatePath("/products");

  return {
    url: result.secure_url,
    publicId: result.public_id,
  };
}
```

### 7.2 Client Component — `SingleImageUpload.tsx`

```tsx
"use client";

import { useState, useTransition } from "react";
import { uploadSingleImage } from "../actions";

export function SingleImageUpload() {
  const [preview, setPreview] = useState<string | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [isPending, startTransition] = useTransition();

  function handleSubmit(formData: FormData) {
    setError(null);

    startTransition(async () => {
      try {
        const result = await uploadSingleImage(formData);
        setPreview(result.url);
      } catch (err) {
        setError(err instanceof Error ? err.message : "Upload failed");
      }
    });
  }

  return (
    <div>
      <form action={handleSubmit}>
        {/* name="image" must match formData.get("image") in the Server Action */}
        <input
          type="file"
          name="image"
          accept="image/jpeg,image/png,image/webp"
          required
        />
        <button type="submit" disabled={isPending}>
          {isPending ? "Uploading…" : "Upload image"}
        </button>
      </form>

      {error && <p>{error}</p>}

      {preview && (
        // eslint-disable-next-line @next/next/no-img-element
        <img src={preview} alt="Uploaded product" width={200} />
      )}
    </div>
  );
}
```

Flow:

```text
User selects one file
        ↓
Form submits FormData to uploadSingleImage
        ↓
Server validates size + MIME type
        ↓
Buffer sent to Cloudinary via upload_stream
        ↓
secure_url returned → save in DB → show preview
```

## 8. Multiple File Upload

### 8.1 Server Action — `app/products/actions.ts`

```ts
"use server";

import { revalidatePath } from "next/cache";
import { uploadToCloudinary } from "@/lib/upload-to-cloudinary";

const MAX_SIZE = 5 * 1024 * 1024;
const ALLOWED_TYPES = ["image/jpeg", "image/png", "image/webp"];
const MAX_FILES = 5;

export async function uploadMultipleImages(formData: FormData) {
  // getAll() returns every file when input has multiple + same name
  const entries = formData.getAll("images");
  const files = entries.filter((entry): entry is File => entry instanceof File);

  if (files.length === 0) {
    throw new Error("At least one image is required");
  }

  if (files.length > MAX_FILES) {
    throw new Error(`Maximum ${MAX_FILES} images allowed`);
  }

  const uploaded: { url: string; publicId: string }[] = [];

  for (const file of files) {
    if (file.size > MAX_SIZE) {
      throw new Error(`"${file.name}" exceeds 5 MB`);
    }
    if (!ALLOWED_TYPES.includes(file.type)) {
      throw new Error(`"${file.name}" has an unsupported type`);
    }

    const result = await uploadToCloudinary(file, "shop/gallery");

    uploaded.push({
      url: result.secure_url,
      publicId: result.public_id,
    });

    // Save each result in the database
    // await db.productImage.create({ productId, url: result.secure_url, ... });
  }

  revalidatePath("/products");

  return uploaded;
}
```

Upload files sequentially in a loop for clarity. For many large files, consider `Promise.all` with a concurrency limit.

### 8.2 Client Component — `MultiImageUpload.tsx`

```tsx
"use client";

import { useState, useTransition } from "react";
import { uploadMultipleImages } from "../actions";

export function MultiImageUpload() {
  const [urls, setUrls] = useState<string[]>([]);
  const [error, setError] = useState<string | null>(null);
  const [isPending, startTransition] = useTransition();

  function handleSubmit(formData: FormData) {
    setError(null);

    startTransition(async () => {
      try {
        const results = await uploadMultipleImages(formData);
        setUrls(results.map((r) => r.url));
      } catch (err) {
        setError(err instanceof Error ? err.message : "Upload failed");
      }
    });
  }

  return (
    <div>
      <form action={handleSubmit}>
        {/* multiple attribute + name="images" → formData.getAll("images") */}
        <input
          type="file"
          name="images"
          accept="image/jpeg,image/png,image/webp"
          multiple
          required
        />
        <button type="submit" disabled={isPending}>
          {isPending ? "Uploading…" : "Upload images"}
        </button>
      </form>

      {error && <p>{error}</p>}

      <div style={{ display: "flex", gap: 8, flexWrap: "wrap" }}>
        {urls.map((url) => (
          // eslint-disable-next-line @next/next/no-img-element
          <img key={url} src={url} alt="Uploaded" width={120} height={120} />
        ))}
      </div>
    </div>
  );
}
```

Flow:

```text
User selects 3 files
        ↓
formData.getAll("images") → [File, File, File]
        ↓
Each file validated + uploaded to Cloudinary
        ↓
Array of secure_urls → saved in DB → gallery preview
```

## 9. Store Metadata in the Database

Cloudinary holds the file. PostgreSQL (or MongoDB) holds the reference:

```ts
// Example Prisma model
model ProductImage {
  id        String   @id @default(cuid())
  productId String
  url       String   // result.secure_url from Cloudinary
  publicId  String   // result.public_id — needed to delete/transform later
  bytes     Int
  width     Int?
  height    Int?
  createdAt DateTime @default(now())
}
```

To delete a file from Cloudinary later:

```ts
import cloudinary from "@/lib/cloudinary";

await cloudinary.uploader.destroy(publicId);
```

## 10. Security Checklist

```text
□ Validate file size, type, and count on the server
□ Never trust accept="" or the original filename
□ Keep CLOUDINARY_API_SECRET server-only (no NEXT_PUBLIC_)
□ Require authentication before upload Server Actions
□ Enforce authorization (user owns the resource being updated)
□ Set bodySizeLimit in next.config.ts for larger files
□ Store public_id in DB so files can be deleted when records are removed
```

## 11. Common Mistakes

### 11.1 Trusting Client Validation

`accept="image/png"` only filters the file picker UI. Always validate `file.type` and `file.size` in the Server Action.

### 11.2 Exposing Cloudinary Secrets

```env
# Wrong — visible in the browser bundle
NEXT_PUBLIC_CLOUDINARY_API_SECRET=...

# Correct — server-only
CLOUDINARY_API_SECRET=...
```

### 11.3 Storing Files on Local Disk in Production

Writing to `/uploads` on the app server breaks in serverless and multi-instance deployments. Use Cloudinary (or S3, etc.) for production file storage.

### 11.4 Skipping Auth in Server Actions

Proxy or page-level auth does not protect Server Actions automatically. Verify the session inside every upload action.

### 11.5 Forgetting `multiple` / `getAll` Mismatch

```text
<input name="images" multiple />  →  formData.getAll("images")
<input name="image" />            →  formData.get("image")
```

The input `name` must match what the Server Action reads.

## 12. Server Action vs Route Handler

| Use case | Recommended |
| -------- | ----------- |
| Form upload from Next.js UI | Server Action |
| Upload from mobile app / external client | Route Handler (`POST /api/upload`) |
| Webhook from Cloudinary | Route Handler |

Both can call the same `uploadToCloudinary` helper — keep provider logic in `lib/`, not inside components.
