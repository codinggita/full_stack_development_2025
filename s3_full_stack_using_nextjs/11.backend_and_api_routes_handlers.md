# 11. Backend & API Routes Handlers

## 1. What Is a Backend API in Next.js?

Next.js can be used not only to render UI but also to create backend
HTTP endpoints.

The exact mechanism depends on the router:

```text
App Router
    ↓
Route Handlers
    ↓
route.ts

Pages Router
    ↓
API Routes
    ↓
pages/api/*.ts
```

Both allow you to build backend APIs inside a Next.js application.

### App Router

```text
app/
└── api/
    └── products/
        └── route.ts
```

### Pages Router

```text
pages/
└── api/
    └── products.ts
```

Both can provide:

```text
GET
POST
PUT
PATCH
DELETE
```

The syntax is different, but the purpose is similar.

---

## 2. App Route Handling

In the App Router, backend endpoints are created using **`route.ts`**.

A `route.ts` file is **not** a React component — it handles HTTP requests and returns HTTP responses.

```text
page.tsx   →  UI / Page
route.ts   →  HTTP API
```

### REST file structure

Use resource-oriented URLs — the HTTP method communicates the operation:

```text
GET    /api/products          →  list / filter
POST   /api/products          →  create

GET    /api/products/123      →  read one
PUT    /api/products/123      →  replace
PATCH  /api/products/123      →  partial update
DELETE /api/products/123      →  delete
```

```text
app/
└── api/
    └── products/
        ├── route.ts          ← collection
        └── [id]/
            └── route.ts      ← individual product
```

Each request can include **method**, **URL**, **headers**, **query parameters**, **route parameters**, and a **body** (for POST, PUT, PATCH).

App Router uses the Web **`Request`** and **`Response`** APIs:

```text
request.method / request.url / request.headers / await request.json()
        ↓
return Response.json(data, { status: 201 })
```

### Collection — `app/api/products/route.ts`

Handles **GET** (with query params) and **POST** (with body + validation):

```ts
// app/api/products/route.ts

import { z } from "zod";

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const productSchema = z.object({
	name: z.string().min(1),
	price: z.number().positive(),
	category: z.string().min(1),
});

// GET /api/products?category=electronics&page=1
export async function GET(request: Request) {
	try {
		const auth = request.headers.get("authorization");
		if (!auth) {
			return Response.json({ error: "Unauthorized" }, { status: 401 });
		}

		const { searchParams } = new URL(request.url);
		const category = searchParams.get("category");
		const page = searchParams.get("page") ?? "1";

		let result = products;
		if (category) {
			result = result.filter((p) => p.category === category);
		}

		return Response.json(
			{ products: result, page: Number(page) },
			{
				status: 200,
				headers: { "X-App-Version": "1.0.0" },
			},
		);
	} catch {
		return Response.json(
			{ error: "Failed to fetch products" },
			{ status: 500 },
		);
	}
}

// POST /api/products
export async function POST(request: Request) {
	try {
		const body = await request.json();
		const result = productSchema.safeParse(body);

		if (!result.success) {
			return Response.json(
				{
					error: "Invalid request body",
					details: result.error.flatten(),
				},
				{ status: 400 },
			);
		}

		const product = { id: Date.now(), ...result.data };
		products.push(product);

		return Response.json(product, { status: 201 });
	} catch {
		return Response.json(
			{ error: "Failed to create product" },
			{ status: 500 },
		);
	}
}
```

### Individual product — `app/api/products/[id]/route.ts`

Uses **route parameters** (`params`) for `/api/products/123`:

```ts
// app/api/products/[id]/route.ts

import { z } from "zod";

type RouteContext = {
	params: Promise<{ id: string }>;
};

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const patchSchema = z.object({
	name: z.string().min(1).optional(),
	price: z.number().positive().optional(),
	category: z.string().min(1).optional(),
});

function findProduct(id: string) {
	return products.find((p) => p.id === Number(id));
}

// GET /api/products/123
export async function GET(_request: Request, context: RouteContext) {
	const { id } = await context.params;
	const product = findProduct(id);

	if (!product) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	return Response.json(product, { status: 200 });
}

// PUT /api/products/123 — replace entire resource
export async function PUT(request: Request, context: RouteContext) {
	const { id } = await context.params;
	const body = await request.json();

	if (!findProduct(id)) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	const updated = { id: Number(id), ...body };
	products = products.map((p) => (p.id === Number(id) ? updated : p));

	return Response.json(updated, { status: 200 });
}

// PATCH /api/products/123?notify=true — partial update
export async function PATCH(request: Request, context: RouteContext) {
	const { id } = await context.params;
	const notify = new URL(request.url).searchParams.get("notify");
	const body = await request.json();
	const result = patchSchema.safeParse(body);

	if (!result.success) {
		return Response.json(
			{ error: "Invalid request body" },
			{ status: 422 },
		);
	}

	const product = findProduct(id);
	if (!product) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	Object.assign(product, result.data);

	return Response.json({ product, notify }, { status: 200 });
}

// DELETE /api/products/123
export async function DELETE(_request: Request, context: RouteContext) {
	const { id } = await context.params;

	if (!findProduct(id)) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	products = products.filter((p) => p.id !== Number(id));
	return new Response(null, { status: 204 });
}
```

> Do not expose internal errors (database messages, stack traces) in API responses. Log details on the server; return a safe public message.

## 3. Page Route Handling

In the Pages Router, backend endpoints are created inside **`pages/api/`**.

Pages Router uses **`NextApiRequest`** and **`NextApiResponse`** with a single default export per file:

```text
req.method / req.url / req.headers / req.query / req.body
        ↓
res.status(200).json(data)
```

### REST file structure

```text
pages/
└── api/
    └── products/
        ├── index.ts      ← collection
        └── [id].ts       ← individual product
```

Same REST URLs as the App Router example:

```text
GET    /api/products?category=electronics
POST   /api/products
GET    /api/products/123
PUT    /api/products/123
PATCH  /api/products/123?notify=true
DELETE /api/products/123
```

### Collection — `pages/api/products/index.ts`

```ts
// pages/api/products/index.ts

import type { NextApiRequest, NextApiResponse } from "next";
import { z } from "zod";

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const productSchema = z.object({
	name: z.string().min(1),
	price: z.number().positive(),
	category: z.string().min(1),
});

export default function handler(req: NextApiRequest, res: NextApiResponse) {
	try {
		if (!req.headers.authorization) {
			return res.status(401).json({ error: "Unauthorized" });
		}

		if (req.method === "GET") {
			const { category, page = "1" } = req.query;

			let result = products;
			if (category) {
				result = result.filter((p) => p.category === String(category));
			}

			res.setHeader("X-App-Version", "1.0.0");
			return res
				.status(200)
				.json({ products: result, page: Number(page) });
		}

		if (req.method === "POST") {
			const result = productSchema.safeParse(req.body);

			if (!result.success) {
				return res.status(400).json({
					error: "Invalid request body",
					details: result.error.flatten(),
				});
			}

			const product = { id: Date.now(), ...result.data };
			products.push(product);
			return res.status(201).json(product);
		}

		return res.status(405).json({ error: "Method not allowed" });
	} catch {
		return res.status(500).json({ error: "Internal server error" });
	}
}
```

### Individual product — `pages/api/products/[id].ts`

Route parameter from **`req.query.id`** for dynamic segment `[id]`:

```ts
// pages/api/products/[id].ts

import type { NextApiRequest, NextApiResponse } from "next";
import { z } from "zod";

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const patchSchema = z.object({
	name: z.string().min(1).optional(),
	price: z.number().positive().optional(),
	category: z.string().min(1).optional(),
});

function findProduct(id: string) {
	return products.find((p) => p.id === Number(id));
}

export default function handler(req: NextApiRequest, res: NextApiResponse) {
	const { id } = req.query;

	try {
		if (req.method === "GET") {
			const product = findProduct(String(id));
			if (!product) {
				return res.status(404).json({ error: "Product not found" });
			}
			return res.status(200).json(product);
		}

		if (req.method === "PUT") {
			if (!findProduct(String(id))) {
				return res.status(404).json({ error: "Product not found" });
			}
			const updated = { id: Number(id), ...req.body };
			products = products.map((p) => (p.id === Number(id) ? updated : p));
			return res.status(200).json(updated);
		}

		if (req.method === "PATCH") {
			const result = patchSchema.safeParse(req.body);
			if (!result.success) {
				return res.status(422).json({ error: "Invalid request body" });
			}

			const product = findProduct(String(id));
			if (!product) {
				return res.status(404).json({ error: "Product not found" });
			}

			Object.assign(product, result.data);
			const notify = req.query.notify;
			return res.status(200).json({ product, notify });
		}

		if (req.method === "DELETE") {
			if (!findProduct(String(id))) {
				return res.status(404).json({ error: "Product not found" });
			}
			products = products.filter((p) => p.id !== Number(id));
			return res.status(204).end();
		}

		return res.status(405).json({ error: "Method not allowed" });
	} catch {
		return res.status(500).json({ error: "Internal server error" });
	}
}
```

### App Router vs Pages Router

| Topic        | App Router                          | Pages Router                   |
| ------------ | ----------------------------------- | ------------------------------ |
| File         | `route.ts`                          | `pages/api/*.ts`               |
| HTTP methods | Named exports (`GET`, `POST`, …)    | `req.method` + `switch` / `if` |
| Request      | Web `Request`                       | `NextApiRequest`               |
| Response     | `Response.json()`                   | `res.status().json()`          |
| Query params | `new URL(request.url).searchParams` | `req.query`                    |
| Route params | `await context.params`              | `req.query` (on `[id]` file)   |
| Body         | `await request.json()`              | `req.body` (already parsed)    |
| Headers      | `request.headers.get()`             | `req.headers`                  |

## 4. Server Actions vs Route Handlers

Server Actions and Route Handlers can both perform server-side
operations, but they are designed for different use cases.

### Server Actions

Server Actions are server-side functions that can be invoked from a
Next.js application, particularly for mutations initiated by the UI.

Example:

```ts
"use server";

export async function createProduct(formData: FormData) {
	const name = formData.get("name");

	await db.product.create({
		data: {
			name: String(name),
		},
	});
}
```

Typical flow:

```text
Next.js Form
     ↓
Server Action
     ↓
Database
```

### Route Handlers

Route Handlers expose HTTP endpoints.

```text
POST /api/products
```

Example:

```ts
export async function POST(request: Request) {
	const body = await request.json();

	const product = await createProduct(body);

	return Response.json(product, {
		status: 201,
	});
}
```

Typical flow:

```text
Browser / Mobile App / External Client
                ↓
       POST /api/products
                ↓
          Route Handler
                ↓
             Database
```

## 5. Server Actions vs Route Handlers — When to Use Which?

| Requirement                                 | Server Actions          | Route Handlers / API Routes |
| ------------------------------------------- | ----------------------- | --------------------------- |
| Form submission from Next.js UI             | ✅                      | ✅                          |
| UI-triggered server mutation                | ✅                      | ✅                          |
| Public HTTP API                             | ❌                      | ✅                          |
| Mobile app consuming API                    | ❌                      | ✅                          |
| Third-party service calling endpoint        | ❌                      | ✅                          |
| REST API                                    | ❌                      | ✅                          |
| Explicit HTTP methods                       | ❌                      | ✅                          |
| JSON API                                    | Not the primary purpose | ✅                          |
| Direct server-side function from Next.js UI | ✅                      | ❌                          |

### Example

If only your Next.js application needs to submit a product form:

```text
Product Form
     ↓
Server Action
     ↓
Database
```

If a mobile application also needs to create products:

```text
Mobile App
     ↓
POST /api/products
     ↓
Route Handler / API Route
     ↓
Database
```

## 6. Recommended Backend Structure

As an application grows, avoid putting all business logic inside
`route.ts` or `pages/api`.

A better structure is:

```text
app/
└── api/
    └── products/
        └── route.ts

lib/
├── db.ts
├── services/
│   └── product.service.ts
└── validations/
    └── product.schema.ts
```

The API layer should primarily handle:

```text
Request
   ↓
Validation
   ↓
Authentication / Authorization
   ↓
Service
   ↓
Response
```

The service layer handles business logic:

```text
Route Handler
      ↓
Product Service
      ↓
Database
```

This separation makes the application easier to maintain and test.

---

## 7. Key Takeaways

- **App Router uses Route Handlers** with `route.ts`.
- **Pages Router uses API Routes** inside `pages/api`.
- Both can be used to build backend HTTP APIs.
- Do not expose sensitive internal errors.
- Route Handlers/API Routes are for HTTP APIs.
- Server Components are primarily for rendering UI.
- Server Actions are useful for server-side actions initiated by your Next.js application.
- Avoid unnecessary internal API calls from Server Components when the data layer can be called directly.
